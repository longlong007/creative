# DecideFlow 产品需求文档（PRD）

| 项 | 内容 |
|---|---|
| 产品名称 | DecideFlow（决断助手） |
| 版本 | MVP v0.1.0 |
| 文档状态 | 已实现对照 |
| 日期 | 2026-08-31 |
| 平台 | iOS / Android / Web（Flutter） |

---

## 1. 背景与问题

人们面对换工作、大额支出、搬家等选择时，容易被情绪、近因和假二分带跑。公开的决策方法（加权评分、预验尸、机会成本等）散落在书和文章里，用户很难在一次真实选择里按步骤用起来。

DecideFlow 用对话把方法变成可执行流程：先澄清问题，再收集信息、生成选项、评估、给出建议，最后留下可复盘的记录。

## 2. 产品目标

### 2.1 成功标准（MVP）

用户在一次使用中能够：

1. 注册并登录。
2. 填写偏好（语言、语气、关注类别、风险偏好、决策节奏）。
3. 从模板或自定义问题开始一次决策。
4. 在 AI 引导下走完澄清 → 收集 → 选项 → 评估 → 建议。
5. 看到并保存决策报告，记录最终选择。
6. 在到期后进入复盘列表完成回顾。

系统必须保存：用户偏好、完整原始对话、结构化工作区、Markdown 报告。

### 2.2 非目标（本版本明确不做）

- 支付、会员、广告。
- 社交分享、多人协作、评论。
- 语音输入、实时流式（SSE）聊天。
- 知识库运营后台、书籍原文入库。
- SSO / OAuth、多租户。
- 系统级推送（APNs / FCM）；MVP 仅应用内到期列表。
- 医疗诊断或心理治疗；健康/关系模板只提供决策框架。

## 3. 用户与场景

### 3.1 目标用户

需要做一次「认真但不专业咨询」级别决策的个人用户。默认中文，可切换英文回复。

### 3.2 主路径

```
注册/登录 → 偏好引导 → 首页 → 选模板或自填问题
    → 对话推进各阶段 → 查看报告并记录决策
    → （默认 14 天后）复盘列表 → 写下回顾
```

### 3.3 关键场景

| 编号 | 场景 | 价值 |
|---|---|---|
| S1 | 换工作 / 接 offer | 把「纠结」拆成标准和选项 |
| S2 | 大额购买或储蓄分配 | 补上机会成本和现金流约束 |
| S3 | 搬家 / 时间分配 | 看可逆性和第二层后果 |
| S4 | 到期复盘 | 对照当时假设与实际结果 |

## 4. 功能需求

### 4.1 账号

| ID | 需求 | 优先级 |
|---|---|---|
| ACC-1 | 邮箱 + 密码注册，密码至少 8 位 | P0 |
| ACC-2 | 登录后签发 JWT，客户端本地保存 | P0 |
| ACC-3 | 未登录不能进入业务页 | P0 |
| ACC-4 | 用户数据按 user_id 隔离 | P0 |

### 4.2 偏好（Onboarding）

注册后必须完成偏好才进首页。

| 字段 | 取值 | 作用 |
|---|---|---|
| language | zh / en | 教练回复语言 |
| tone | professional / warm / concise / socratic | 交互风格 |
| categories | career, finance, health, relationship, purchase, life（多选） | 模板排序 |
| risk_tolerance | low / medium / high | 建议时的风险措辞（LLM 模式） |
| decision_speed | careful / balanced / fast | 每阶段最少对话轮次：3 / 2 / 1 |

设置页可再次修改偏好。

### 4.3 问题模板

后端内置 12 个模板（含「自定义问题」）。按用户关注类别排序。用户也可在输入框自填问题后开始。

### 4.4 决策对话

单向阶段：

| 阶段 | 用户能感到的事 |
|---|---|
| 澄清 clarify | 把问题写成可判定的一句话，补成功标准和截止时间 |
| 收集 collect | 补约束、利益相关者、不可逆点；有密钥时可联网 |
| 选项 options | 看到至少 3 个可比较选项（含维持现状/试验） |
| 评估 evaluate | 对照标准看到综合分 |
| 建议 recommend | 看到建议、理由、风险与复盘提醒 |
| 已记录 recorded | 最终选择写入报告，不可再继续原对话 |

顶部展示阶段条。对话中助手消息可附带知识库命中信息（存 metadata，不强制展示原文）。

### 4.5 记录、报告、复盘

- 进入「建议」后生成 Markdown 报告；用户记录选择时再固化一版。
- 记录时可选手中选项或自定义选择，并写备注。
- `review_in_days` 默认 14，范围 1–365。
- `GET /reviews/due` 返回已到期未复盘的决策；用户提交复盘笔记后 status=reviewed。

### 4.6 知识库与联网

- 种子文档为原创方法摘要，禁止书籍原文。
- 每次用户发言检索 top-4 片段注入教练。
- 配置 Pinecone + OpenAI 走云向量；否则本地哈希向量。
- 配置 Tavily 且阶段为收集/评估时允许联网；失败不阻断对话。

## 5. 体验要求

- 默认 UI 中文；教练内容跟随 language。
- Material 3 浅色。Web / iOS / Android 同一套页面。
- 发送失败时保留输入框内容。
- 发送中禁用重复提交。

## 6. 数据与合规要点

- 密码单向哈希（PBKDF2-SHA256），不明文存储。
- JWT HS256，默认 7 天。
- 密钥只存在服务端环境变量。
- 健康/关系场景文案需标明非诊疗、非心理治疗。
- 知识库不入库用户表；对话、工作区、报告属于用户。

## 7. 度量（MVP 只预留，不做看板）

后续可统计：完成 onboarding 率、走到 recommend 的会话占比、记录决策率、到期复盘完成率。本版本不实现分析后台。
