## 1. 领域模型

### 1.1 用户 User

| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID 字符串 | 主键 |
| email | 唯一 | 小写存储 |
| password_hash | 字符串 | `pbkdf2$120000$salt$hash` |
| display_name | ≤80 | 默认取邮箱前缀 |
| preferences | JSON | 见偏好结构 |
| onboarding_done | bool | 首次 PUT preferences 后为 true |
| created_at / updated_at | datetime | UTC |

偏好 JSON：

```json
{
  "language": "zh",
  "tone": "warm",
  "categories": ["career", "finance"],
  "risk_tolerance": "medium",
  "decision_speed": "balanced"
}
```

### 1.2 决策 Decision

| 字段 | 说明 |
|---|---|
| stage | clarify / collect / options / evaluate / recommend / recorded |
| status | active / recorded / reviewed |
| workspace | 结构化投影，见 1.4 |
| report_markdown | 建议阶段生成，记录时重写固化 |
| review_at | 记录时 = now + review_in_days |
| reviewed_at / review_notes | 复盘提交时写入 |
| template_id | 可空 |
| category | 默认 life |

### 1.3 消息 Message

| 字段 | 说明 |
|---|---|
| role | user / assistant / system |
| content | 原文 |
| stage | 该条产生时所处（或推进后的）阶段 |
| extra | opening / retrieved / web / degraded / report / review |
| created_at | 排序依据 |

创建决策时写入一条 assistant opening。记录决策时写入 role=system 的报告快照。复盘时追加一条 user 笔记。

### 1.4 工作区 workspace

```json
{
  "title": "要不要换工作",
  "stage": "evaluate",
  "problem_statement": "...",
  "criteria": [{"name": "成长空间", "weight": 2}],
  "constraints": ["下个月必须决定"],
  "options": [
    {"id": "uuid", "title": "采取新方案", "description": "...", "scores": {"成长空间": 4.0}, "total": 3.8}
  ],
  "recommendation": {
    "option_id": "uuid",
    "label": "采取新方案",
    "rationale": "...",
    "caveats": "..."
  },
  "recorded_choice": {
    "option_id": "uuid 或 null",
    "label": "先谈薪再决定",
    "notes": "..."
  },
  "report_markdown": "# 决策报告：..."
}
```

对话是事实源；workspace 允许教练增量 patch。

## 2. 阶段状态机

实现：`backend/app/domain/stages.py`。

```
clarify → collect → options → evaluate → recommend → recorded
```

- `advance_stage(current)`：前进一步；recorded 再进一步抛 `ValueError`。
- `can_record(stage)`：仅 `recommend` 为 true。API 层转 409。
- 不提供回退 API。字段仍是字符串，日后可加「退回收集」而不改表结构。

`turns_needed(speed)`：fast=1，balanced=2，careful=3，未知当 2。启发式教练用「当前阶段用户发言次数 ≥ 该值」作为自动前进条件。`recommend` 不因轮次自动进入 `recorded`，必须走 record 接口。

## 3. 启发式教练

实现：`backend/app/domain/coach.py`。无 OpenAI 密钥时的默认路径。

每轮：

1. `_absorb`：澄清阶段合并 problem_statement、抽取或默认标准；收集阶段把分点写入 constraints；选项阶段解析「还是/或者/vs」补选项。
2. 若轮次足够且非 recommend：按阶段补选项、打分、生成 recommendation 与 report，然后 `advance_stage`。
3. `_compose`：按 language/tone/当前 stage 生成话术，并点名检索到的框架标题。

默认选项：用户提到的备选，否则「采取新方案 / 维持现状 / 推迟 90 天并补信息」。评分：选项下标造成稳定分差，避免并列。综合分 = Σ(分数×权重)/Σ权重。

## 4. LLM 教练

实现：`backend/app/services/llm.py`。

- 系统提示包含偏好、当前 workspace、retrieved、web。
- 要求模型返回 JSON：`text`、`stage`、`workspace_patch`。
- 进入 recommend 且尚无报告时由服务端 `build_report`。
- 任何异常（含空 text）回退 HeuristicCoach，并标记 `degraded=true`。

## 5. 对话编排 ChatOrchestrator

实现：`backend/app/services/chat.py`。

**create_decision**：解析模板 → 预填 criteria → 插入 Decision + opening Message。

**add_user_message**：

- recorded 拒绝。
- `rag.search(title + 用户句, top_k=4)`。
- collect/evaluate 时 `search.search`，异常则空列表。
- `coach.reply` 后分别插入 user（stage=旧）与 assistant（stage=新）消息。
- 同步 title / report_markdown。

**record**：校验 can_record → 写入 recorded_choice → 重生成报告 → status=recorded、stage=recorded、设置 review_at → system 消息存报告。

## 6. RAG 与入库

| 组件 | 行为 |
|---|---|
| `parse_markdown_docs` | `knowledge/*.md`，首行 `#` 为 title |
| ingest | 空库才自动 ingest；`scripts/ingest.py` 可强制重入 |
| HashEmbedder | 中英 token 的 MD5 投到 256 维并 L2 归一 |
| LocalVectorStore | `{id: {vector, metadata}}` 写 JSON |
| PineconeVectorStore | 无 index 则按 dim + cosine + serverless 创建 |

检索 query 为「标题 + 用户本轮文本」。命中写入 assistant.extra.retrieved。

种子文档（原创，非书摘）：加权评分、10/10/10、预验尸、遗憾最小化、逆向思考、机会成本、第二层后果、OODA、Cynefin 简版、四核对。

## 7. 报告

`build_report(workspace, language)` 输出 Markdown，含问题、标准、约束、选项综合分、建议、用户最终选择。中英两套标题。

## 9. 客户端详细设计

### 9.1 路由守卫

| 条件 | 重定向 |
|---|---|
| 无 token 且非 login/register | /login |
| 有 token 且未 onboarding | /onboarding |
| 已 onboarding 且位于 login/register/onboarding | /home |

### 9.2 页面职责

| 页面 | 行为 |
|---|---|
| Login/Register | 调 session.login/register；错误用横幅 |
| Onboarding | 编辑 Preferences；保存后若可 pop 则返回设置，否则守卫送去首页 |
| Home | 并行拉 decisions 与 due reviews；到期卡片；进行中/已记录分组 |
| Templates | 自定义问题或点模板 → createDecision → 进聊天 |
| Chat | 阶段条、气泡、发送；recommend 或非 active 显示报告入口 |
| Report | Markdown 报告；active 时选选项+备注并 record |
| Reviews | 到期列表；先看报告再对话框提交笔记 |
| Settings | 改偏好、退出（清 token） |

### 9.3 错误

Dio 超时 连接 20s / 读 60s。失败展示 `detail` 或「网络错误」。聊天失败把原文写回输入框。

## 12. 已知限制（设计内）

- 聊天非流式。
- 阶段不可后退。
- 复盘无系统推送。
- HashEmbedder 召回弱于真实 embedding，仅保证种子文档可区分。
- JWT 刷新令牌未做，过期需重新登录。
